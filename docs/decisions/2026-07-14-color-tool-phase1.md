# 開發調色工具第一階段決策記錄

日期：2026-07-14

## 目的

原本的 `DevColorPanel` 只適合開發者快速拖色票。本階段將它改成老闆也能自行比較、保存並交付配色方向的引導式工具，同時維持純前端、GitHub Pages 靜態部署與既有 `ThemeProvider` API。

## 顏色角色與套用方式

沿用既有內部命名，不做大範圍 rename：

| 面板用語 | 內部欄位 | 用途 |
|---|---|---|
| 主色 | `base` | `--bg`，並由 `deriveBaseShades()` 推導 `--surface` |
| 輔色 | `primary` | CTA、按鈕、選中狀態，由 `deriveShades()` 推導色階 |
| 點綴色 | `secondary` | 標題、徽章、小面積裝飾，由 `deriveShades()` 推導色階 |

三個輸入一律驗證完整 `#RRGGBB`。面板可顯示與複製推導出的 surface，但不允許獨立修改，避免美術交付色與網站實際推導規則分岔。文字色仍固定為 `#E2E8F0` / `#9A9AB0`。

## localStorage 資料格式

目前套用中的三色沿用既有 key：

```json
{
  "primary": "#7c3aed",
  "secondary": "#f43f5e",
  "base": "#0f0f23"
}
```

- key：`gw-theme-colors`
- 讀取時驗證三色，壞資料清除並回到專案預設。

自訂方案採可升級的 versioned 格式：

```json
{
  "version": 1,
  "schemes": [
    {
      "id": "1720950000000-ab12cde",
      "name": "穩重科技紫",
      "colors": {
        "primary": "#7c3aed",
        "secondary": "#f43f5e",
        "base": "#0f0f23"
      }
    }
  ]
}
```

- key：`gw-saved-themes-v1`
- 名稱去除前後空白，限制 1–40 字。
- 自訂方案最多 50 組；讀取與序列化都會截斷到上限，UI 達上限時以 inline 錯誤及 `aria-live` 提醒先刪除方案，避免 localStorage 與畫面列表無界增長。
- 容器、版本、id、名稱與所有色碼都要驗證；非法項目不進入 UI，重複 id 只保留第一筆。
- 解析後若發現部分壞資料，會把有效項目重新存成乾淨格式；完全無有效資料則清除 key。

## UX 取捨

- 面板改成可捲動的浮動工作區，寬度不超過 viewport；375px 可完整操作，不造成水平溢出。
- 所有主要操作至少約 44px，icon-only 按鈕有 `aria-label`；鍵盤 focus 使用不受可調色影響的白色 outline + 黑色 ring 雙層提示，避免使用者把輔色調成背景近似色後看不到焦點。
- 開啟面板會把焦點移入關閉按鈕；從面板內或浮動按鈕關閉時，焦點都回到啟動按鈕。複製與保存結果透過 `aria-live` 回饋。
- HEX 於失焦或 Enter 時才驗證與套用，避免使用者輸入到一半就看到錯誤；Escape 可恢復目前已套用值。
- 每次「打開面板」才建立 session snapshot。`恢復本次調整` 回到該 snapshot；`重置專案預設` 回到產品原始配色，兩者語意分開。
- Undo/redo 只涵蓋本次面板開啟後的調整。history 上限 50 步，避免色票連續事件造成無界記憶體成長；套用新分支會清空 redo。
- 「目前、原始、本次初始、其餘預設主題」放在快速比較區；自訂方案緊接保存表單列出，可一鍵套用或刪除，避免把同一方案重複顯示兩次。
- 配色摘要包含目前可辨識的方案名稱（若有）、三個輸入色、推導 surface 與固定文字色，讓美術能直接使用，不必從截圖猜色。
- 方案刪除不另加確認視窗：資料只存在本機、影響低，而且刪除單筆方案不改變目前網站配色。這讓快速比較流程保持輕量。
- localStorage 寫入失敗時，新增或刪除仍會反映在目前頁面的 session，但訊息會明確說明重整後不會保留或可能再次出現，不把記憶體內成功誤報為已持久保存。
- storage getter 本身也可能因瀏覽器安全政策拋出 `SecurityError`；取得 storage 與寫入都包在同一安全邊界內，失敗時一律走上述 session-only 行為。
- `aria-live` 回饋以遞增 nonce 重新掛載訊息節點，相同的「已複製」或錯誤訊息連續發生時仍會再次被輔助科技宣布，不依賴 timer。

## 第二階段未納入

- WCAG 對比度檢查與建議修正。
- 以 URL query 分享配色、跨裝置同步或後端帳號。
- 更亮／更暗／更鮮／更灰等引導式微調。
- 漸層、字型、陰影、圓角或每個區塊的獨立設計 token。
- 自動切換文字深淺色；目前刻意維持固定文字色，極端亮背景可能可讀性不足。
